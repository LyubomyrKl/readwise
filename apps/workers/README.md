# Workbench workers

One Python process (`main.py`) that runs two RabbitMQ consumers:

| Worker | Queue | Does |
|---|---|---|
| `workers/extraction-worker` | `extract_request` | downloads the uploaded PDF/EPUB from MinIO, extracts text (pdfplumber / ebooklib), stores markdown in the `extractions` bucket, then forwards the request to `summary_request` with every summary option |
| `workers/summarization-worker` | `summary_request` | segments the text, runs the async summarization pipeline against the Ollama host, checkpoints per section in the `checkpoints` bucket, stores JSON in `summaries`, records type and strategy on the book row |

Shared code (`shared/`): Prisma access (`database.py`), pika helpers (`messaging.py`), boto3 helpers (`s3_storage.py`).

## Run

- In Docker: the root `docker-compose.yml` builds `apps/workers/Dockerfile` from the repository root.
- Locally: Python 3.11, then

  ```bash
  cp .env.example .env            # point at the Docker infrastructure and your Ollama host
  pip install -e ".[dev]"
  prisma generate                 # one-time, generates the Python client from schema.prisma
  python main.py
  ```

Configuration is read from the environment (see `.env.example`). `PIPELINE_MODE` selects the `fast`, `balanced` or `quality` preset; the strategy comes from each request.

## Tests

```bash
../../scripts/test-workers.sh    # pytest inside python:3.11-slim with the pinned dependencies
pytest                           # if you already have a 3.11 environment with the dev extra installed
```

The schema copy `schema.prisma` is generated by `../../sync-prisma.sh` from `apps/api/prisma/schema.base.prisma`; do not edit it directly.
